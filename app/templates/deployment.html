rocket_launchGuide de Déploiement — NEMBA Report Generator

arrow_back Retour au wizard
Objectif : Déployer NEMBA Report Generator en une seule commande grâce au task runner makefile.ps1 — sur Windows (dev / service NSSM / Docker), avec exposition Internet via Cloudflare Tunnel, ou sur Linux / cloud (alternative).

rocket_launch Quick start (1 commande)

Sur Windows, après git clone :

cd nemba-report
.\makefile.ps1 start

Le script effectue 12 vérifications avec auto-fix, puis propose un menu interactif (Dev / NSSM / Docker) et propose ensuite Cloudflare Tunnel.

Variantes utiles

# Production : git pull + backup uploads + service NSSM
.\makefile.ps1 start -Profile prod -Pull -Backup

# Mode CI / serveur headless (sans navigateur, sans pare-feu)
.\makefile.ps1 start -NoBrowser -NoFirewall

# Aide complète
.\makefile.ps1 help

check_circle Pré-requis

Windows (recommandé)

  • PowerShell 5.1+ ou 7+
  • uv 0.4+ (gestion Python rapide)
  • Python 3.11+ (auto-installé par uv)
  • git 2.x
  • NSSM 2.24+ (pour mode service Windows)
  • Docker Desktop (pour mode container)
  • cloudflared (optionnel, tunnel)

Linux / cloud

  • Ubuntu 20.04+ / Debian 11+
  • Python 3.11+, uv ou pip
  • Nginx (reverse proxy) ou Cloudflare Tunnel
  • Render / Railway / Fly.io (PaaS)
  • RAM 2 GB min., 10 GB de disque
Astuce : Sur Windows, start installe automatiquement Docker et cloudflared via winget si absents, et fournit le lien de téléchargement manuel en cas d'échec.

description Workflow Windows recommandé

1. Installation initiale

1
Installer uv (une seule fois sur la machine)
powershell -c "irm https://astral.sh/uv/install.ps1 | iex"
2
Cloner le projet
git clone <URL_DU_REPO> nemba-report && cd nemba-report
3
Lancer le démarrage assisté
.\makefile.ps1 start
Le reste (Python 3.11, dépendances, Tailwind CLI, CSS, police d'icônes, dossiers uploads/logs, SECRET_KEY, Docker, Cloudflared) est automatique.

2. Mode dev local

Lancement uvicorn --reload avec ouverture auto du navigateur.

.\makefile.ps1 start
# (puis : 1)

# Ou directement :
.\makefile.ps1 dev
.\makefile.ps1 dev -Port 8080

3. Mode service Windows (NSSM)

Crée un service Windows nemba-report qui :

  • Démarre automatiquement au boot (SERVICE_AUTO_START)
  • Redémarre auto en cas de crash (5 s de délai)
  • Logge dans logs/nemba-report.out.log et .err.log
  • Tourne via uv run uvicorn app.main:app --host 0.0.0.0 --port 8000

Création du service :

.\makefile.ps1 start
# (puis : 2 → o pour confirmer)

Commandes de gestion :

nssm status nemba-report
nssm restart nemba-report
nssm stop nemba-report
nssm remove nemba-report confirm     # désinstaller

# Logs en direct
Get-Content logs\nemba-report.out.log -Tail 50 -Wait
Pré-requis : NSSM doit être installé et dans le PATH (nssm.cc/download).

4. Mode Docker

Le Dockerfile à la racine est multi-stage (builder + runtime python:3.11-slim), avec utilisateur non-root, healthcheck HTTP, libs cairo/freetype.

.\makefile.ps1 start
# (puis : 3)
# Le script propose d'installer Docker Desktop via winget si absent.

Commandes utiles :

docker ps -f name=nemba-report
docker logs -f nemba-report
docker restart nemba-report
docker stop nemba-report
docker rm -f nemba-report

Le conteneur expose 0.0.0.0:8000 et monte app/static/uploads/ en volume pour persister les uploads.

5. Cloudflare Tunnel (exposition Internet)

Après le choix du mode, le script demande :

Voulez-vous aussi exposer via Cloudflare Tunnel ? (o/n)

Deux modes disponibles

Quick Tunnel

URL aléatoire *.trycloudflare.com (éphémère).

  • Pas de compte requis
  • Idéal pour démo / test rapide
  • Disparaît à la fermeture

Tunnel nommé (production)

Domaine personnalisé persistant : https://rapport.votre-domaine.com

  • Compte Cloudflare gratuit + domaine ajouté
  • Authentification via navigateur
  • Génère ~/.cloudflared/config.yml
  • TLS automatique

Pour faire de cloudflared un service Windows persistant :

cloudflared service install

check_circle Pré-flight checks de start

Le script vérifie 12 points avant tout lancement, et corrige automatiquement quand c'est possible :

1.  uv installé
2.  Profil .env (-Profile dev/staging/prod) chargé
3.  Dépendances Python (uv sync)
4.  Python ≥ 3.11
5.  SECRET_KEY auto-généré si vide dans .env
6.  Tailwind CLI (auto-téléchargé si absent)
7.  CSS Tailwind à jour (auto-rebuild si templates plus récents)
8.  Police Material Symbols Outlined
9.  Dossiers uploads/ et logs/ (auto-créés)
10. Smoke test : import app.main sans erreur
11. Espace disque > 500 MB + état git
12. Port libre

admin_panel_settings Variables d'environnement

Le fichier .env est créé automatiquement depuis .env.example au premier lancement.

# Port d'écoute (défaut: 8000)
# PORT=8000

# Root path FastAPI quand l'app est servie derrière un reverse proxy
# ROOT_PATH=/neembacoaching

# Version applicative (sinon: court SHA git, sinon timestamp)
# APP_VERSION=

# Clé secrète des sessions (auto-générée par 'start' si vide)
# SECRET_KEY=
Profils multi-environnement : créer .env.dev, .env.staging, .env.prod puis lancer avec -Profile <nom>. Le bon .env est copié à chaque démarrage.

share Déploiement Linux (alternative)

Service systemd + Nginx

1. Installation

sudo apt update && sudo apt install -y python3.11 build-essential nginx git
curl -LsSf https://astral.sh/uv/install.sh | sh
sudo git clone <URL> /opt/nemba-report
cd /opt/nemba-report && uv sync

2. Build du CSS Tailwind (équivalent Linux)

curl -L https://github.com/tailwindlabs/tailwindcss/releases/download/v3.4.17/tailwindcss-linux-x64 \
     -o tools/tailwindcss && chmod +x tools/tailwindcss
./tools/tailwindcss -c tailwind.config.js \
                    -i app/static/css/tailwind.input.css \
                    -o app/static/css/tailwind.css --minify

3. Service systemd

# /etc/systemd/system/nemba-report.service
[Unit]
Description=NEMBA Report Generator
After=network.target

[Service]
Type=simple
User=www-data
Group=www-data
WorkingDirectory=/opt/nemba-report
ExecStart=/root/.local/bin/uv run uvicorn app.main:app --host 127.0.0.1 --port 8000
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
sudo systemctl daemon-reload
sudo systemctl enable --now nemba-report

4. Reverse proxy Nginx + SSL Let's Encrypt

# /etc/nginx/sites-available/nemba-report
server {
    listen 80;
    server_name votre-domaine.com;
    client_max_body_size 50M;

    location /static/ {
        alias /opt/nemba-report/app/static/;
        expires 1y;
        add_header Cache-Control "public, immutable";
    }
    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
sudo ln -s /etc/nginx/sites-available/nemba-report /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d votre-domaine.com

public Déploiement cloud (Render)

Créer render.yaml à la racine puis Render → New + → Web Service → connecter le repo. SSL automatique inclus.

services:
  - type: web
    name: nemba-report
    env: python
    plan: free
    buildCommand: |
      pip install uv
      uv sync --frozen
      curl -L https://github.com/tailwindlabs/tailwindcss/releases/download/v3.4.17/tailwindcss-linux-x64 -o /tmp/tailwindcss
      chmod +x /tmp/tailwindcss
      /tmp/tailwindcss -c tailwind.config.js -i app/static/css/tailwind.input.css -o app/static/css/tailwind.css --minify
    startCommand: uv run uvicorn app.main:app --host 0.0.0.0 --port $PORT
    envVars:
      - key: PYTHON_VERSION
        value: 3.11.0
Railway / Fly.io : le Dockerfile du projet fonctionne tel quel, configurer le port 8000 exposé.

admin_panel_settings Sécurité

  • Pare-feu Windows : start propose la création automatique de la règle (UAC requis).
  • HTTPS : Cloudflare Tunnel fournit TLS automatiquement. Sinon Let's Encrypt côté Nginx.
  • .env : ne jamais commit (déjà dans .gitignore).
  • SECRET_KEY : auto-généré (32 octets aléatoires) par start si vide.
  • Image Docker : tourne en utilisateur non-root nemba.
  • Headers : ajouter via Nginx ou Cloudflare (X-Frame-Options, CSP, etc.).

restart_alt Dépannage

Port déjà utilisé 
Get-NetTCPConnection -LocalPort 8000 | Select-Object OwningProcess
Stop-Process -Id <PID> -Force
# Ou changer de port :
.\makefile.ps1 start -Port 8080
Icônes Material Symbols affichées comme texte

Police absente. Lancer :

.\makefile.ps1 icons
CSS non à jour après modification d'un template

Le pre-flight de start détecte automatiquement. Sinon manuellement :

.\makefile.ps1 build-css
Service NSSM ne démarre pas 
nssm status nemba-report
Get-Content logs\nemba-report.err.log -Tail 50

Causes typiques : port pris, deps manquantes, .env corrompu.

Container Docker crash au démarrage 
docker logs nemba-report --tail 100
docker exec -it nemba-report bash    # debug interactif
Cloudflared : authentification échouée

Si pas de compte / domaine Cloudflare :

  1. Sign up gratuit : dash.cloudflare.com/sign-up
  2. Sites → Add a site (plan Free)
  3. Pointer les nameservers du domaine vers Cloudflare
  4. Relancer .\makefile.ps1 start → option Cloudflared → mode 2
