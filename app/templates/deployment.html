🚀 Guide de Déploiement - NEMBA Report Generator

← Retour au wizard
🎯 Objectif : Ce guide vous accompagne dans le déploiement de l'application NEMBA Report Generator, que ce soit sur un serveur interne ou sur une plateforme cloud comme Render.

📋 Prérequis

💻 Serveur Interne

  • Ubuntu 20.04+ / CentOS 8+ / Debian 11+
  • Python 3.9+ (recommandé 3.11)
  • RAM : 2GB minimum, 4GB recommandé
  • CPU : 2 cœurs minimum
  • Stockage : 10GB d'espace libre

☁️ Render (Cloud)

  • Compte Render gratuit ou payant
  • Repository Git (GitHub/GitLab)
  • Domaine personnalisé (optionnel)
  • Variables d'environnement

🏠 Déploiement Serveur Interne

1. Installation des dépendances système

Ubuntu/Debian :

sudo apt update
sudo apt install python3.11 python3.11-venv python3.11-dev build-essential
sudo apt install nginx apache2-utils

CentOS/RHEL :

sudo yum install python311 python311-devel gcc gcc-c++ make
sudo yum install nginx httpd-tools

2. Configuration de l'application

1
Cloner le projet
cd /opt && sudo git clone [URL_REPO] nemba-report
2
Créer l'environnement virtuel
cd nemba-report && python3.11 -m venv venv
3
Installer les dépendances
source venv/bin/activate && pip install -r requirements.txt

3. Configuration Nginx + Gunicorn

Service systemd :

sudo nano /etc/systemd/system/nemba-report.service
[Unit]
Description=NEMBA Report Generator
After=network.target

[Service]
Type=notify
User=www-data
Group=www-data
WorkingDirectory=/opt/nemba-report
Environment=PATH=/opt/nemba-report/venv/bin
ExecStart=/opt/nemba-report/venv/bin/gunicorn --bind unix:/run/nemba-report.sock --workers 3 --worker-class uvicorn.workers.UvicornWorker app.main:app
ExecReload=/bin/kill -s HUP $MAINPID
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target

Configuration Nginx :

sudo nano /etc/nginx/sites-available/nemba-report
server {
    listen 80;
    server_name votre-domaine.com;
    
    client_max_body_size 50M;
    
    location /static/ {
        alias /opt/nemba-report/app/static/;
        expires 1y;
    }
    
    location / {
        proxy_pass http://unix:/run/nemba-report.sock;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

4. Activation et démarrage

# Activer le site Nginx
sudo ln -s /etc/nginx/sites-available/nemba-report /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx

# Démarrer le service
sudo systemctl enable nemba-report
sudo systemctl start nemba-report
sudo systemctl status nemba-report

☁️ Déploiement sur Render

1. Préparation du repository

1
Créer un fichier render.yaml
Ajoutez ce fichier à la racine de votre projet : 
# render.yaml
services:
  - type: web
    name: nemba-report
    env: python
    plan: free
    buildCommand: pip install -r requirements.txt
    startCommand: uvicorn app.main:app --host 0.0.0.0 --port $PORT
    envVars:
      - key: PYTHON_VERSION
        value: 3.11.0

2. Configuration sur Render

1
Connecter votre repository
• Allez sur render.com
• Cliquez sur "New +" → "Web Service"
• Connectez votre compte GitHub/GitLab
2
Configurer le service
• Repository : Sélectionnez votre repo
• Branch : main
• Root Directory : laissez vide
• Environment : Python 3
3
Variables d'environnement
• PORT : 10000 (automatique)
• PYTHON_VERSION : 3.11.0
• HOST : 0.0.0.0

3. Commandes de build et démarrage

Build Command :

pip install -r requirements.txt

Start Command :

uvicorn app.main:app --host 0.0.0.0 --port $PORT

🔒 Configuration SSL/HTTPS

Serveur Interne - Let's Encrypt

# Installation Certbot
sudo apt install certbot python3-certbot-nginx

# Génération du certificat
sudo certbot --nginx -d votre-domaine.com

# Renouvellement automatique
sudo crontab -e
# Ajouter : 0 12 * * * /usr/bin/certbot renew --quiet

Render - SSL automatique

✅ Avantage Render : Le SSL est automatiquement configuré pour tous les services web. Aucune configuration supplémentaire nécessaire !

📊 Monitoring et Maintenance

Serveur Interne

Vérifier le statut :

sudo systemctl status nemba-report
sudo journalctl -u nemba-report -f

Logs Nginx :

sudo tail -f /var/log/nginx/nemba-report_error.log
sudo tail -f /var/log/nginx/nemba-report_access.log

Render

📈 Monitoring : Render fournit des métriques automatiques : CPU, RAM, requêtes, temps de réponse. Accessibles dans le dashboard.

🔧 Résolution de problèmes

Problèmes courants :

🚫 Erreur 502 Bad Gateway :
  • Vérifiez que le service nemba-report est démarré
  • Contrôlez les permissions du socket Unix
  • Vérifiez les logs : sudo journalctl -u nemba-report
📁 Erreur d'upload :
  • Vérifiez client_max_body_size dans Nginx
  • Contrôlez les permissions du dossier uploads
  • Serveur interne : sudo chown -R www-data:www-data /var/lib/nemba-report
🐍 Erreur Python :
  • Vérifiez la version Python (3.9+ requis)
  • Réinstallez les dépendances : pip install -r requirements.txt
  • Vérifiez les variables d'environnement
☁️ Problèmes Render :
  • Vérifiez les logs dans le dashboard Render
  • Contrôlez les variables d'environnement
  • Redéployez le service si nécessaire
